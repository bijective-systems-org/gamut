# Reading map

For an engineer or agent opening mestra cold. It points into the documents
that own each subject and repeats none of them.

## What mestra is, and is not

An open file format, HDF5 laid out as valid netCDF-4, for the results of a
simulation study and the surrogate models fitted to them, with readers and
writers in Python, C++, MATLAB and Julia.

- [README.md](README.md): what a file holds, install, the first file.
- [docs/guide.md](docs/guide.md): the model in plain words, one runnable
  example per concept ([docs/examples/](docs/examples/)).
- [docs/comparison.md](docs/comparison.md): how it relates to VTK, CGNS,
  netCDF-CF and the machine-learning dataset formats.
- [docs/compatibility.md](docs/compatibility.md): what each implementation
  can and cannot do, and the non-goals that follow from the format being a
  data contract (who establishes correspondence, ownership and modelling
  policy).

## Who owns what

| Subject | Authority |
|---|---|
| Meaning of a file, validator rules (E/W codes), versioning | [SPEC.md](SPEC.md); version handling is section 28 |
| Expected outcome for every case | the corpus in [vectors/](vectors/README.md), generated by `vectors/generate.py` and checked by `vectors/check.py` |
| Names, argument order and messages across languages | [docs/api-conventions.md](docs/api-conventions.md) |
| Per-language limits | [docs/compatibility.md](docs/compatibility.md) |
| Why the model is shaped this way | [docs/design-notes.md](docs/design-notes.md), [docs/mappings.md](docs/mappings.md) |
| Which rows train a model, how a callable executes, file lineage | the producing or consuming tool, never mestra |

No implementation is the reference. The spec and the corpus are, and a
behaviour one language has and the corpus does not pin is a gap to close in
the corpus. A change to the contract follows [CONTRIBUTING.md](CONTRIBUTING.md):
spec, corpus and every implementation together, with its compatibility
decision under SPEC section 28.

## Boundaries worth knowing before an edit

- **Callables.** A reader that does not own a callable type copies its
  dictionary unchanged and refuses to evaluate it (SPEC section 10). The
  owning tool registers the type (on import in Python and Julia, by its
  registration call in C++ and MATLAB); mestra never imports or loads a
  plugin to find one. The refusal says how to register.
- **Alignment and support identity.** `support_id` hashes structure, not
  geometry; the producer establishes correspondence
  ([compatibility.md](docs/compatibility.md#who-establishes-correspondence)).
- **Damaged files.** libhdf5 can fault on a damaged file; the defence is a
  process boundary ([compatibility.md](docs/compatibility.md#damaged-files)).
- **Package version is not format version.** Python, Julia and CMake carry
  the package version; the file carries `format = "mestra/0"`.
